# 놀러와스키샵 정적 블로그 및 네이버 사이트링크 설계

## 목표

놀러와스키샵 홈페이지에 동일 도메인 기반의 정적 블로그 영역을 추가한다. 네이버가 홈페이지의 주요 메뉴와 글을 독립 문서로 발견할 수 있도록 실제 URL, 내부 링크, sitemap, canonical, 구조화 데이터를 일관되게 구성한다.

성공 기준은 네이버 검색 결과에 메뉴가 반드시 노출되는 것이 아니라, 검색엔진이 메뉴 후보로 사용할 수 있는 크롤링 가능한 정보 구조를 제공하는 것이다. 사이트링크 노출과 순서는 네이버가 자동으로 결정한다.

## 범위

### 포함

- `/blog/index.html` 블로그 허브
- 첫 글 3개
  - `/blog/muju-ski-rental.html`
  - `/blog/muju-lift-ticket.html`
  - `/blog/muju-ski-price.html`
- 데스크톱 내비게이션·모바일 메뉴·푸터의 `블로그` 실제 링크
- 블로그 전용 최소 스타일 파일
- 각 페이지의 고유 title, description, canonical, OG 메타
- 각 글의 가시적 `Article` JSON-LD와 BreadcrumbList
- sitemap.xml에 블로그 허브와 글 3개 추가
- JavaScript 없이도 제목·첫 답변·본문·링크가 HTML에 존재하도록 구성

### 제외

- Supabase 기반 블로그 CMS
- 관리자 글쓰기 화면, 댓글, 회원 기능, 이미지 업로드
- 자동 글 생성·자동 발행·외부 블로그 동기화
- 네이버 사이트링크 노출을 보장하는 조작
- 확인되지 않은 후기·가격·영업시간·리프트권 판매 사실 추가
- 이용약관 페이지 신설(별도 작업으로 유지)

## 정보 구조와 검색 의도

블로그 글은 키워드 변형별로 복제하지 않고 검색 의도별로 하나씩 만든다.

| URL | 대표 의도 | 핵심 내용 |
|---|---|---|
| `/blog/muju-ski-rental.html` | 무주렌탈샵·무주스키장렌탈샵 | 렌탈 품목, 예약 방법, 슬로프 앞 배달, 방문 준비 |
| `/blog/muju-lift-ticket.html` | 무주리프트권·무주스키장리프트권 | 3·4·6시간권, 주중·주말 요금, 시즌 기준일 |
| `/blog/muju-ski-price.html` | 무주스키장가격 | 장비·의류·헬멧·고글 및 리프트권 비용을 표로 안내 |

블로그 허브는 세 글을 요약하고 각 글로 연결한다. 홈페이지에서는 `무주블로그` 또는 `블로그`라는 실제 `<a href>`로 허브를 연결한다.

## 콘텐츠 규칙

- 각 글의 `<h1>`은 title과 같은 주제를 사용한다.
- 첫 문단은 질문에 대한 직접 답변으로 시작한다.
- 가격·시즌·운영 조건에는 `2026/27 시즌 기준`과 실제 갱신일을 표시한다.
- 가격과 조건은 현재 홈페이지에 공개된 사실만 사용한다.
- FAQ는 화면에 보이는 문장과 JSON-LD를 동일하게 유지한다.
- 글끼리 관련 글 링크를 연결하고 홈페이지의 예약·가격 영역으로도 연결한다.
- 정적 HTML에 본문을 기록하며 JavaScript는 부가 기능에만 사용한다.

## 기술 설계

- 기존 GitHub Pages 정적 배포를 그대로 사용한다.
- 블로그 페이지 공통 스타일은 `blog/blog.css`에 둔다.
- 페이지별 메타와 JSON-LD는 각 HTML에 직접 둔다.
- canonical은 `https://www.nolleowaski.com/blog/...`로 고정한다.
- JSON-LD의 Article author/publisher는 실제 운영 주체만 사용한다.
- OG 이미지는 기존 공개 이미지 또는 페이지별 실제 이미지로 연결하고, 새 이미지가 없으면 과장된 썸네일을 만들지 않는다.
- sitemap의 `<lastmod>`는 실제 파일 변경일과 맞춘다.

## 검증 기준

배포 전 다음을 로컬에서 확인한다.

1. 각 신규 URL이 파일로 존재하고 상대 링크가 404가 아니다.
2. 각 페이지가 title, description, canonical, h1을 정확히 1개씩 가진다.
3. 각 글의 raw HTML에 첫 답변과 핵심 키워드가 존재한다.
4. Article JSON-LD와 BreadcrumbList JSON-LD가 JSON으로 파싱된다.
5. sitemap에 신규 URL 4개가 들어가고 기존 URL이 유지된다.
6. `node --check`로 기존 index.html 인라인 JS 문법을 확인한다.
7. 배포 후 홈페이지·블로그 허브·글 3개·sitemap이 HTTP 200인지 확인한다.

## 운영 후 측정

배포일을 기준선으로 기록하고 14일 후 Google Search Console과 네이버 Search Advisor에서 다음을 비교한다.

- `site:nolleowaski.com` 색인 URL 수
- 키워드별 노출·클릭·평균 순위
- 블로그 글별 유입 여부
- 네이버 검색 결과의 사이트링크 또는 관련 문서 노출 여부

사이트링크가 즉시 생기지 않아도 실패로 판단하지 않는다. 검색엔진이 페이지를 발견하고 충분한 신호를 쌓는 시간이 필요하다.
